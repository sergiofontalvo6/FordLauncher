# FordLauncher 2.10.26 — Corrección del asistente con internet

## Causa real
- La clave API y la red estaban bien: Gemini devolvía HTTP 400 con `Invalid JSON payload received. Unknown name "thinkingConfig": Cannot find field.` El campo `thinkingConfig` se enviaba fuera de `generationConfig`, por lo que el asistente mostraba el toast genérico «Sin conexión a internet o clave API no válida».
- Ya no se usa el toast genérico. Ahora el aviso indica la causa: `Error API 404: modelo no encontrado`, `Error API 400/403: clave inválida`, `Error API 429: cuota agotada`, `Error SSL/Red: …`, `Error de red: …`.

## Correcciones
- `thinkingConfig.thinkingBudget = 0` se envía **dentro** de `generationConfig`, como exige la API v1beta.
- El modelo solicitado `gemini-2.5-flash` ya devuelve HTTP 404 («no longer available to new users»); se usa `gemini-3.5-flash-lite` (respaldo `gemini-flash-lite-latest`), que sí responde HTTP 200 con esta clave. Equivalente de baja latencia: `thinkingLevel: MINIMAL` en Gemini 3.x (`thinkingBudget: 0` se conserva para 2.5).
- La clave se sanea al leerla (`.trim()`, sin `\r` ni `\n`) y viaja en la cabecera `x-goog-api-key`, nunca en los logs.
- `logcat` registra con etiqueta `GeminiClient` el código HTTP exacto, el cuerpo del error de Google y el `Throwable` completo ante fallos de red/SSL.
- TLS en Android 8.1: `ConnectionSpec.MODERN_TLS`, fábrica TLS propia y `ProviderInstaller.installIfNeededAsync` por reflexión (sin añadir dependencia GMS).
- El toast de error del asistente también se refleja en `logcat`.

## Sin cambios
- No se tocan el nombre, el vehículo, la voz en nube, la clave API guardada, los wallpapers ni los accesos personalizados.
